# Where the matrices are *actually* transformed (render time, not metadata time)

This page nails down one point that's easy to get wrong, and that
[`c.md`](c.md) and [`c2.md`](c2.md) only touch in passing:

> **`compute_fragment_info` never changes the count matrices, references, or
> positions. It only *labels* them. The real reshaping — splitting and dropping
> columns — happens much later, at render time, inside
> `save_logo_with_rect_gaps` → `apply_count_filter`.**

If you remember one thing: **labels are computed early, data is transformed late, and
`reduction_on_ref` is the single switch that drives both.**

## Two jobs that look like one

Both jobs read the same inputs (count matrices + reference windows + positions) and
both are gated on the same `reduction_on_ref` flag. That's why they're easy to
conflate. But they run at different times and produce different things:

| | `compute_fragment_info` | `apply_count_filter` |
|---|---|---|
| When | During metadata collection, right after `build_mutation_aggregates` | During rendering, inside `save_logo_with_rect_gaps` |
| Where | [multi_regions.jl:143](../../src/generation/mutagenesis/multi_regions.jl#L143) | EntroPlots `helpers.jl:150` (called from `plot_logo_w_arr_gaps.jl:121`) |
| Reads | count mats, refs, positions | count mats, refs, positions |
| Returns | **labels** — `fragment_count`, `span`, `group_id`, `button_text` | **new data** — filtered count mats, new positions, new refs |
| Mutates the arrays? | **No** — read-only | **Yes** — this is the transformation |
| Uses `EntroPlots.count_fragments` (counts runs) | `EntroPlots.apply_count_filter` (extracts runs) |

Same reference-matching logic underneath (`filter_counts_by_reference` +
`group_to_ranges`), applied twice: once to *count* the fragments (for labels), once to
*materialize* them (for the picture). They agree by construction — that's the whole
point of reusing the logic — but only the second one touches the data.

The arrays built in step 3 of [`c2.md`](c2.md) are the *only* real copy. They travel,
untouched, through `MotifData` and `MotifMetadata` into the renderer. The first (and
only) time anything reshapes them is inside the render call.

## What `apply_count_filter` actually does

EntroPlots, `helpers.jl:150-167`:

```julia
function apply_count_filter(count_matrices, starting_indices, reference_pfms; tol=1e-9)
    new_counts, new_starts, new_refs = [], Int[], BitMatrix[]
    for (counts, start, ref) in zip(count_matrices, starting_indices, reference_pfms)
        keep = filter_counts_by_reference(counts, ref; tol=tol)   # columns that DIFFER from reference
        isempty(keep) && continue                                 # whole region matches → drop it
        for range in group_to_ranges(keep)                        # contiguous runs of kept columns
            push!(new_counts, view(counts, :, range))             # one sub-matrix per run
            push!(new_starts, start + first(range) - 1)           # its true start position
            push!(new_refs,   view(ref, :, range))
        end
    end
    new_counts, new_starts, new_refs
end
```

Three outcomes per input region:

- **Unchanged** — every column differs from the reference → one run → same region.
- **Dropped** — every column matches → `keep` empty → `continue` → region disappears
  (this is the "reduction" that shrinks a triplet to a pair).
- **Split** — a matching column sits in the interior → kept columns break into two runs
  → **one region becomes two sub-matrices** with their own starts (this is the growth
  case: a singleton can render as `2_regions`).

That's why, after this step, a region's matrix width and count no longer have to match
`filter_len` or `motif_size` — the arrays have genuinely been rebuilt.

Where it's called (EntroPlots `plot_logo_w_arr_gaps.jl:117-128`, inside
`logoplot_with_rect_gaps`):

```julia
if !isnothing(reference_pfms) && filter_by_reference       # filter_by_reference = meta.reduction_on_ref
    count_matrices, starting_indices, reference_pfms =
        apply_count_filter(count_matrices, starting_indices, reference_pfms; tol=filter_tolerance)
    isempty(count_matrices) && error("All columns match reference - nothing to plot after filtering")
end
```

Note the failure mode: if the filter removes *everything*, it throws. The per-motif
`try` in `render_one_motif!` catches that and simply skips the card.

## Consequences worth remembering

- **`meta.count_matrices` is the raw, unfiltered data.** Anything reading `meta`
  downstream of metadata collection (sorting, top-movers, CSV export) sees the
  original arrays, *not* the reference-filtered ones. Only the pixels in the PNG
  reflect the filter.
- **The labels and the picture can only diverge if the flag differs between them —
  and it can't.** Both read `meta.reduction_on_ref`, so `group_id` ("2_regions") and
  the number of drawn regions always agree.
- **With `reduction_on_ref = false` (your current default), neither step transforms
  anything.** `compute_fragment_info` returns `fragment_count = motif_size`, and
  `apply_count_filter` isn't called at all — the logo draws the arrays exactly as
  `obtain_count_and_reference_matrices` built them.
