# The mutagenesis rendering workflow (end to end)

This is the big-picture companion to [`c.md`](c.md). Where `c.md` zooms **in** on
the single step that builds the count/reference/position matrices
(`obtain_count_and_reference_matrices`), this page zooms **out**: it walks the whole
path from the input DataFrames to the saved logo PNGs, and tells you which file and
function does each job.

Read this first for the map, then jump into `c.md` when you reach the matrix-building
step, and [`save_logo_with_rect_gaps.md`](save_logo_with_rect_gaps.md) when you reach
the drawing step.

## Step by step

### 1. Entry point — `plot_motifs_mut_case`
File: [`src/run_thru_mut.jl:2`](../../src/run_thru_mut.jl#L2).

You hand it two DataFrames — `contributions_df_filtered` (singletons) and `dfs` (the
multi-motif tables, `dfs[1]`=pairs, `dfs[2]`=triplets, …) — plus the `data` object. It
bundles all the knobs into one `MutationRegionConfig` ([types.jl:73](../../src/generation/core/types.jl#L73))
and drives everything below.

Two config flags decide most of the interesting behavior, and both are **off by
default** in this entry point:

- `off_region_search` — the indel-realignment path. See [`c.md`](c.md) and the note
  in step 3.
- `reduction_on_ref` — reference-based region reclassification. See step 5.

### 2. Choosing `df_mutated` — `prepare_and_collect_mutation_metadata`
File: [`src/generation/mutagenesis/multi_regions.jl:46`](../../src/generation/mutagenesis/multi_regions.jl#L46).

It loops over motif sizes `[1, 2, 3, …]`. On each pass it selects the table that step
3 will call `df_mutated`:

| Motif size | `df_mutated` source | Code |
|---|---|---|
| 1 (singletons) | `filter_and_rename_for_mutagenesis(contributions_df, data)` — filter to common length, Pareto-filter, rename `:filter_index→:m1`, `:position→:m1_position` | [singletons.jl:20](../../src/generation/mutagenesis/singletons.jl#L20) |
| ≥ 2 | `dfs[size-1]`, filtered to `most_common_length_indices` | [multi_regions.jl:82](../../src/generation/mutagenesis/multi_regions.jl#L82) |

So `df_mutated` is a **different table each iteration**, and it comes from `dfs`
*only* for the multi-region sizes.

### 3. Aggregating + building matrices — `build_mutation_aggregates`
File: [`src/generation/mutagenesis/multi_regions.jl:112`](../../src/generation/mutagenesis/multi_regions.jl#L112).

Groups `df_mutated` by the motif's filter/position columns, builds the sorted keys and
the per-key medians/counts, then calls the matrix builder:

```julia
count_matrices_vec, reference_matrices_vec, adjusted_positions_vec =
    obtain_count_and_reference_matrices(…; off_region_search = config.off_region_search)
```

**This is the hand-off to [`c.md`](c.md)** — that page explains the inputs, the
per-region count accumulation, the optional ±3 nt reference search, and the
overlap-merge. The three returned dicts (count matrices, reference windows, integer
start positions) are the raw material for everything after this.

> **On `off_region_search`:** it exists for **indels** — an insertion/deletion shifts a
> motif off its recorded position, so the code searches ±3 nt for the true reference
> match and merges any regions that then overlap. With no indels it only risks adding
> spurious 1–2 nt drift, so it is off by default. The overlap-merge is gated on the
> same flag, so turning it off also turns merging off.

### 4. Packing into `meta` — `MotifData` → `MotifMetadata`
Files: [`types.jl:171`](../../src/generation/core/types.jl#L171) (data) and
[`types.jl:198`](../../src/generation/core/types.jl#L198) (metadata).

For each key, the three arrays get wrapped into a `MotifData`, which is then combined
with the config and fragment info into a `MotifMetadata` — the `meta` object the
renderer reads. Convenience field access (`meta.count_matrices`, `meta.dpi`, …) is
provided by a custom `getproperty` that forwards to the nested structs
([types.jl:237](../../src/generation/core/types.jl#L237)).

### 5. Classifying regions — `compute_fragment_info` (`reduction_on_ref`)
File: [`src/generation/mutagenesis/multi_regions.jl:143`](../../src/generation/mutagenesis/multi_regions.jl#L143).

This computes each motif's `group_id`, `button_text`, and `span` — i.e. whether it's
labeled `single_region`, `2_regions`, etc.

- `reduction_on_ref = false` (current default): region count = `motif_size` exactly.
- `reduction_on_ref = true`: calls `EntroPlots.count_fragments`, which counts
  **contiguous runs of columns that differ from the reference**. This can make the
  region count **smaller** (a whole region matches the reference and drops out) *or*
  **larger** (a reference-matching column in the middle of a region splits it in two).
  So a "triplet" can render as `2_regions`, and a "singleton" can render as
  `2_regions`. The same flag also filters columns at draw time via
  `filter_by_reference` ([multi_regions.jl:770](../../src/generation/mutagenesis/multi_regions.jl#L770)).

### 6. Sorting for display — `sort_metadata_for_registration`
File: [`src/generation/mutagenesis/multi_regions.jl:671`](../../src/generation/mutagenesis/multi_regions.jl#L671).

Puts the collected metadata into render order — by default a binned lexicographic
sort (group → cluster-median bin → NND bin → Shapley bin → count) so single-region
motifs come first and near-equal motifs aren't split on meaningless decimals.

### 7. Rendering each motif — `render_one_motif!`
File: [`src/generation/mutagenesis/multi_regions.jl:758`](../../src/generation/mutagenesis/multi_regions.jl#L758),
called in a loop from `register_mutation_region_motifs!`
([multi_regions.jl:878](../../src/generation/mutagenesis/multi_regions.jl#L878)).

For each `meta` it writes the logo PNG:

```julia
EntroPlots.save_logo_with_rect_gaps(
    meta.count_matrices, meta.positions, meta.total_length, paths.png.abs;
    reference_pfms = meta.references, dpi = meta.dpi, rna = meta.use_rna,
    filter_by_reference = meta.reduction_on_ref, …)
```

It also emits the influence plot, optional indicator/NND plot, positional CSV, and
registers the motif's card into the HTML/JSON output.

#### How the logo is actually drawn

Inside `save_logo_with_rect_gaps`
([EntroPlots `plot_logo_w_arr_gaps.jl:210`](../../src/generation/mutagenesis/multi_regions.jl#L761),
delegating to `logoplot_with_rect_gaps`) the render happens in five moves. This is the
[`save_logo_with_rect_gaps.md`](save_logo_with_rect_gaps.md) material in miniature:

1. **Validate** the count matrices (no negatives, no zero-sum columns) and, if given,
   check one reference per matrix.
2. **Filter by reference** (only when `filter_by_reference = meta.reduction_on_ref`):
   drop every column that matches the reference. A region can split into several
   pieces here, or vanish entirely — the same `group_to_ranges` logic step 5 used to
   classify regions. If *all* columns match, it errors ("nothing to plot"); the
   caller's per-motif `try` catches that and just skips the card.
3. **Normalize counts → PFM** — each matrix becomes a probability matrix via
   `counts ./ sum(counts, dims=1)`. So the matrices carry raw counts right up until
   render; the frequency conversion is the last moment.
4. **Lay out along the shared axis** — `get_offset_from_start(starting_indices, pfms,
   total_length)` turns the integer start positions (`meta.positions`) into per-region
   x-offsets and the gap widths between them. The gap between region *i* and *i+1* is
   `startᵢ₊₁ − endᵢ − 1`; EntroPlots asserts every gap is ≥ 0, which is exactly the
   invariant the overlap-merge in step 3 protects. Gaps are log-compressed so a huge
   intron doesn't dwarf the letters, but stays visible.
5. **Draw and save** — for each region, `logoplot!` stacks the letters at its offset
   (coloring/height from the PFM, reference-relative if a reference was passed); then
   `arrowplot!` draws the rectangle marks in the gaps; x-tick labels are the real
   coordinates `start : start + width − 1`. Finally `savefig(p, paths.png.abs)` writes
   the PNG.

The net effect: **each region of the motif is one small logo, placed at its true
sequence coordinate, with a compressed rectangle gap standing in for the stretch
between regions** — which is why the whole thing is called a "logo with rect gaps."

### 8. Assembling the site — `render_and_save_outputs!`
File: [`src/run_thru_mut.jl:71`](../../src/run_thru_mut.jl#L71) onward.

Wraps the registered cards into the HTML pages and builds the summary (top-movers),
generalization, statistics, and readme pages, then optionally shrinks the PNGs.

## The two flags, in one place

Both default to **off** in `plot_motifs_mut_case`, so a fresh run does neither of the
things below unless you opt in.

| Flag | What it changes | Where | Default |
|---|---|---|---|
| `off_region_search` | ±3 nt reference realignment for indel-shifted motifs, plus overlap-merge of regions | [reference_matching.jl:58](../../src/generation/mutagenesis/reference_matching.jl#L58), [:145](../../src/generation/mutagenesis/reference_matching.jl#L145) | `false` |
| `reduction_on_ref` | Recount regions as contiguous non-reference-matching stretches (can shrink *or* grow the count); filter matching columns from the logo | [multi_regions.jl:143](../../src/generation/mutagenesis/multi_regions.jl#L143), [:770](../../src/generation/mutagenesis/multi_regions.jl#L770) | `false` |
